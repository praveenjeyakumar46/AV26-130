## 🎯 System Overview

Your Legal AI system uses a **two-model pipeline**:

```
User Query → [Mistral] → Keywords/Context → [Qwen] → Legal Answer
```

**Mistral (Keyword Extraction):** Extracts legal keywords, identifies constitutional articles, classifies query intent.

**Qwen2.5-Instruct (Answer Generation):** Generates bilingual (English + Tamil) legal explanations with citations.

---

## 🖥 GPU Compatibility

The system **auto-detects your GPU** at startup and applies the best possible settings — no manual tuning needed.

| Tier | GPU Examples | VRAM | Mistral Model | Qwen Model | Seq Len | Batch | LoRA r |
|------|-------------|------|--------------|-----------|---------|-------|--------|
| **1** | RTX 2050, 2060, 3050 | 4–6 GB | Mistral-7B (4-bit) | Qwen2.5-7B (4-bit) | 512 | 1 | 8 |
| **2** | RTX 3060, 3070, 2070, 2080 | 8–12 GB | Mistral-7B (4-bit) | Qwen2.5-7B (4-bit) | 1024 | 2 | 16 |
| **3** | RTX 3080, 3090, 4070, 4080 | 16–20 GB | Mistral-7B | Qwen2.5-7B | 2048 | 4 | 32 |
| **4** | RTX 4090, 5090, A100 | 24 GB+ | Mistral-7B | Qwen2.5-7B | 4096 | 8 | 64 |

**Note:** **Mistral-7B** and **Qwen2.5-7B** are used for all tiers. Tier 1 and 2 use 4-bit quantization and gradient checkpointing to fit lower VRAM.

**Precision is also auto-selected:**
- RTX 20xx (Turing) → `float16` (fp16)
- RTX 30xx / 40xx / 50xx (Ampere+) → `bfloat16` (bf16) — more stable, slightly better quality

**Gradient checkpointing** is automatically enabled on Tier 1 and Tier 2 to save VRAM.

## 🚀 Installation

### Step 1 — Navigate to the training directory

```bash
cd "D:\VS code codes\project\backend\model_training"
```

### Step 2 — Install PyTorch with CUDA

Training uses your NVIDIA GPU (e.g. RTX 2050). The default `pip install torch` is **CPU-only**, so you must install a CUDA build explicitly.

**1. Uninstall any existing PyTorch (so the correct build is used):**

```bash
pip uninstall -y torch torchvision torchaudio
```

**2. Install PyTorch with CUDA** — pick the index that matches your Python version:

| Python | CUDA index | Command |
|--------|------------|---------|
| **3.13** | cu124 (CUDA 12.4) | `pip install torch --index-url https://download.pytorch.org/whl/cu124` |
| 3.10–3.12 | cu121 (CUDA 12.1) | `pip install torch --index-url https://download.pytorch.org/whl/cu121` |

> The download is large (~2.5 GB). Wait for it to finish.

**3. Verify CUDA is available**

Run:

```bash
python -c "import torch; print('CUDA available:', torch.cuda.is_available()); print('Device:', torch.cuda.get_device_name(0) if torch.cuda.is_available() else 'N/A')"
```

**Expected output when GPU is detected:**
```
CUDA available: True
Device: NVIDIA GeForce RTX 2050
```

If you see `CUDA available: False`, see [Troubleshooting](#training-is-using-cpu-instead-of-gpu). Optional: `nvidia-smi` to inspect GPU from the command line.

### Step 3 — Install all other requirements

```bash
pip install -r requirements.txt
```

### Step 4 — Hugging Face login (required for Mistral-7B / Qwen2.5-7B)

Both models are **gated**: accept the license and log in, or you get **401 Unauthorized**.

1. **Create an account** (if needed): [huggingface.co/join](https://huggingface.co/join)
2. **Accept the license** on each model page and click **Agree and access repository**:
   - [mistralai/Mistral-7B-v0.1](https://huggingface.co/mistralai/Mistral-7B-v0.1)
   - [Qwen/Qwen2.5-7B-Instruct](https://huggingface.co/Qwen/Qwen2.5-7B-Instruct)
3. **Create a token** (Read): [huggingface.co/settings/tokens](https://huggingface.co/settings/tokens)
4. **Log in:** run `huggingface-cli login` and paste the token, or set `HF_TOKEN=your_token` in the same terminal before training.

## 🧠 Understanding the Models

### LoRA (Low-Rank Adaptation)
Trains only ~1–2% of parameters using small adapter matrices. 3–4x less memory than full fine-tuning, 2–3x faster, with 95%+ of the quality. Only the adapter weights are saved (~200–500 MB).

### 4-bit Quantization
Stores model weights in 4 bits instead of 16 bits — 4x less VRAM with under 2% accuracy loss. Makes it possible to train on consumer GPUs with as little as 4 GB VRAM.

### Gradient Checkpointing
Trades compute for memory — recomputes activations during the backward pass instead of storing them. Automatically enabled on Tier 1 and Tier 2. Adds ~20% training time but saves 30–40% VRAM.

## 🐛 Troubleshooting

### Training is using CPU instead of GPU

**Check if PyTorch sees your GPU:**
```bash
python -c "import torch; print('CUDA:', torch.cuda.is_available()); print('Device:', torch.cuda.get_device_name(0) if torch.cuda.is_available() else 'N/A')"
```

If it prints `CUDA: False`, you have the CPU-only PyTorch build. Reinstall with a CUDA build — see [Step 2 — Install PyTorch with CUDA](#step-2--install-pytorch-with-cuda) for the full steps. Summary:

```bash
pip uninstall -y torch torchvision torchaudio
# Python 3.13:
pip install torch --index-url https://download.pytorch.org/whl/cu124
# Python 3.10–3.12:
pip install torch --index-url https://download.pytorch.org/whl/cu121
```

Then run the verify command again; you should see `CUDA: True` and your GPU name.

**Check GPU usage while training:**
```bash
nvidia-smi -l 1
```
If `GPU-Util` stays at 0% and `Used Memory` is near 0 during training, PyTorch is still using CPU — reinstall with the CUDA index above.

### 401 Unauthorized / Repository Not Found

Models are gated. Accept the license on [Mistral-7B](https://huggingface.co/mistralai/Mistral-7B-v0.1) and [Qwen2.5-7B](https://huggingface.co/Qwen/Qwen2.5-7B-Instruct), then run `huggingface-cli login` or set `HF_TOKEN=your_token`. See [Step 4 — Hugging Face login](#step-4--hugging-face-login-required-for-mistral-7b--qwen25-7b).

### CUDA Out of Memory

The config already applies the safest settings for your GPU tier. If you still get OOM:
```bash
# In config.py — override manually
MISTRAL_CONFIG["batch_size"] = 1
MISTRAL_CONFIG["gradient_accumulation_steps"] = 16
MISTRAL_CONFIG["max_seq_length"] = 256
```

Or add `gradient_checkpointing=True` to TrainingArguments in `train_mistral.py`.

### Poor Results / Loss Not Decreasing

```python
# In config.py — increase epochs and lower learning rate
MISTRAL_CONFIG["num_epochs"] = 5
MISTRAL_CONFIG["learning_rate"] = 1e-4
MISTRAL_CONFIG["lora_r"] = 32
```

### Model Not Downloading

Download with Git LFS and set local paths in `config.py`:
```bash
git lfs install
git clone https://huggingface.co/mistralai/Mistral-7B-v0.1
git clone https://huggingface.co/Qwen/Qwen2.5-7B-Instruct
```
```python
MISTRAL_MODEL_NAME = "C:/models/Mistral-7B-v0.1"
QWEN_MODEL_NAME    = "C:/models/Qwen2.5-7B-Instruct"
```

### Resume After a Crash

Edit the trainer call in `train_mistral.py` or `train_qwen.py`:
```python
trainer.train(resume_from_checkpoint=True)
```

### Switching GPUs (e.g. RTX 2050 today → RTX 3060 tomorrow)

**No code changes needed.** The script auto-detects the GPU and switches tier (e.g. Tier 1 → Tier 2). You’ll see:

| | RTX 2050 (Tier 1) | RTX 3060 (Tier 2) |
|---|-------------------|-------------------|
| **VRAM** | 4–6 GB | 8–12 GB |
| **Batch size** | 1 | 2 |
| **Seq length** | 512 | 1024 |
| **LoRA r** | 8 | 16 |
| **Training time** | ~6–10 h (Mistral), ~4–7 h (Qwen) | ~3–5 h, ~2–3.5 h |
| **Quality** | Good | Slightly better (longer context, larger LoRA) |

**Resuming on the new GPU:** You can copy your checkpoint from the 2050 run to the 3060 machine and run with `resume_from_checkpoint=True`. The **model** (Mistral-7B / Qwen-7B) is the same; only batch size and LoRA rank differ. Resuming from a Tier 1 checkpoint on Tier 2 usually works; if you hit errors, start a fresh run on the 3060 (same data, better tier settings).

### Tamil Text Not Extracted

If `prepare_data.py` shows `⚠ No text extracted from Tamil PDF`, run from `backend/`:
```bash
python ocr_tamil_pdf.py --input database/data/constitution_tamil.pdf --output database/data/constitution_tamil_unicode.txt --dpi 300
```

## 🦙 Ollama and your trained model

- **Ollama** = app uses it for chat (backend calls Ollama API). **Training** = fine-tunes Mistral/Qwen on your data and saves to `./models/...`.
- **Resume training:** use `trainer.train(resume_from_checkpoint=True)` in the trainer script.
- **Train from your checkpoint:** in `config.py` set `MISTRAL_MODEL_NAME = "./models/mistral_keyword_finetuned"` and a new `MISTRAL_OUTPUT_DIR`; no HF login needed for local path.
- **Use trained model in the app:** either add a Python inference API that loads your checkpoint, or merge LoRA → GGUF and create a custom Ollama model, then set `OLLAMA_MISTRAL_MODEL` in the backend.
